# modxMCP

Управление сайтом **MODX Revolution 2.x** через ИИ по протоколу MCP.

> Ветка `main` — версия 2.0 в разработке, несовместимая с 1.x. Клиент 2.x работает только
> с компонентом 2.x на сайте. Спецификация: [docs/spec-2.0.md](docs/spec-2.0.md).

## Установка на сайт

1. Скачать `modxmcp-*.transport.zip` из **Releases** и установить: **Дополнения → Установщик → Загрузить пакет**.
2. Открыть **Дополнения → modxMCP** и создать токен с нужным уровнем доступа (`read`, `content`,
   `develop` или `admin`). Токен показывается один раз. При обновлении с 1.x прежний токен
   продолжает работать как `admin`.

## Подключение

В `.mcp.json` проекта указать адрес сайта и токен, затем переподключить MCP (`/mcp`):

```json
{
  "mcpServers": {
    "modx": {
      "command": "npx",
      "args": ["-y", "github:dampilov94/mcp-component"],
      "env": {
        "MODX_MCP_SITE_URL": "http://САЙТ/assets/components/modxmcp/api.php",
        "MODX_MCP_TOKEN": "ваш-токен"
      }
    }
  }
}
```

## Настройки HTTP-клиента

Дополнительные переменные `env`:

- `MODX_MCP_TIMEOUT_MS` — тайм-аут HTTP-запроса, по умолчанию `60000` мс.
- `MODX_MCP_MAX_REQUEST_BYTES` — лимит тела запроса, по умолчанию `1048576` байт.
- `MODX_MCP_MAX_RESPONSE_BYTES` — лимит ответа, по умолчанию `4194304` байт.

Значения — положительные целые числа. В `MODX_MCP_SITE_URL` указывайте конечный адрес
API: редиректы отключены, токен на другой адрес не пересылается. Для большого ответа
лимит клиента должен соответствовать серверной настройке `modxmcp.max_response_bytes`.

Если запись прервалась по тайм-ауту или отмене, PHP мог уже выполнить действие. В ошибке
будет `request_id`: проверьте его через `modx_request_status`. Для повтора того же
вызова передайте этот ID в `_request_id`, сохранив остальные аргументы. Завершённый
запрос вернёт сохранённый ответ; незавершённый запрос с неизвестным результатом повторно
не выполняется.

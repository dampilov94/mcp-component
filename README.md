# modxMCP

Управление сайтом **MODX Revolution 2.x** через ИИ по протоколу MCP.

> Ветка `main` — версия 2.0 в разработке, несовместимая с 1.x. Клиент 2.x работает только
> с компонентом 2.x на сайте. Спецификация: [docs/spec-2.0.md](docs/spec-2.0.md).

## Установка на сайт

1. Скачать `modxmcp-*.transport.zip` из **Releases** и установить: **Дополнения → Установщик → Загрузить пакет**.
2. Открыть **Дополнения → modxMCP → Токены** и создать токен с нужным уровнем доступа (`read`,
   `content`, `develop`, `admin` или «Только черновики» (`draft_only`). Токен показывается один раз, вместе с готовыми настройками
   клиента для этого сайта (выбор клиента на странице).

### Режим «Только черновики»

Создайте такой токен на странице «Токены», если клиент должен готовить правки для согласования.
Клиент читает ресурсы сайта, создаёт неопубликованный черновик существующей страницы и меняет
текстовые поля своего черновика через `modx_update`. Ссылку предпросмотра открывает пользователь
с активным сеансом в менеджере MODX. В блоке «Черновики» администратор проверяет изменения и
применяет их к странице или удаляет черновик.

В этом режиме поля принимают обычный текст. Публикация, изменение шаблонов, TV и файлов
доступны только через другие подходящие роли.

В менеджере сайта с HTTPS администратор может нажать «Поделиться предпросмотром» в блоке
«Черновики». Ссылку может открыть любой, у кого она есть, в течение 30 минут. Страница
показывает изменённые текстовые поля без разметки. После правки черновика выпустите новую
ссылку. Обычный предпросмотр открывает страницу целиком в сеансе менеджера MODX.

### Переход с modxMCP 1.x

Если на сайте установлен modxMCP 1.x, переходите на 2.0 через отдельную установку:

1. Сделайте резервную копию БД и файлов. Сохраните нужные значения настроек `modxmcp.*`,
   старый аудит и свои файлы из каталогов компонента. Проверьте, что используемые сайтом
   статические файлы вынесены из `core/components/modxmcp/` и `assets/components/modxmcp/`.
   При деинсталляции 1.10.0 удаляются и дополнительные файлы внутри каталога компонента.
2. В установщике MODX деинсталлируйте modxMCP 1.x и удалите запись его пакета.
3. Установите пакет 2.0, при необходимости настройте его заново и создайте новый токен.
   Замените конфигурацию MCP-клиента на вариант со страницы «Токены» и переподключите его.

## Подключение

### По HTTP, без Node (основной способ)

Сайт сам отвечает по MCP (Streamable HTTP) на том же адресе `api.php`, с теми же токенами.
Клиенту нужны адрес и заголовок `X-MCP-Token: <токен>` (`Authorization: Bearer <токен>` тоже
принимается, но Apache с PHP через FastCGI — частая настройка хостингов — не передаёт его в PHP,
и подключение получает 401). Готовый текст для каждого
клиента показывается на странице «Токены» при создании токена. Пример, Claude Code
(`.mcp.json` в папке проекта; затем `/mcp`):

```json
{
  "mcpServers": {
    "modx": {
      "type": "http",
      "url": "http://САЙТ/assets/components/modxmcp/api.php",
      "headers": { "X-MCP-Token": "ваш-токен" }
    }
  }
}
```

| Клиент | Файл | Ключи |
|---|---|---|
| Claude Code | `.mcp.json` | `mcpServers.modx`: `type: "http"`, `url`, `headers` |
| Codex CLI | `~/.codex/config.toml` | `[mcp_servers.modx]`: `url`, `env_http_headers = { "X-MCP-Token" = "MODX_MCP_TOKEN" }` (токен в переменной `MODX_MCP_TOKEN`) |
| Gemini CLI | `settings.json` | `mcpServers.modx`: `httpUrl`, `headers` |
| opencode | `opencode.json` | `mcp.servers.modx`: `type: "remote"`, `url`, `oauth: false`, `headers` |
| Cursor | `.cursor/mcp.json` | `mcpServers.modx`: `url`, `headers` |
| VS Code | `.vscode/mcp.json` | `servers.modx`: `type: "http"`, `url`, `headers` |
| Cline | `cline_mcp_settings.json` | `mcpServers.modx`: `type: "streamableHttp"`, `url`, `headers` |
| Zed | `settings.json` | `context_servers.modx`: `url`, `headers` |

Особенности HTTP-режима: список инструментов обновляется при переподключении клиента (мост
Node узнаёт об изменениях сразу); моста нет, поэтому нет и запоминания ревизий между
вызовами, передавайте `expected_revision` сами. Заголовок `Origin` принимается только с
адресом самого сайта или из настройки `modxmcp.allowed_origins` (запросы без `Origin`,
то есть консольных клиентов, это не касается). Подключения claude.ai и ChatGPT (OAuth)
не поддерживаются.

Клиенты без поддержки HTTP (в том числе Claude Desktop) подключаются через `mcp-remote`:

```
npx mcp-remote http://САЙТ/assets/components/modxmcp/api.php --transport http-only --header "X-MCP-Token:${MODX_MCP_TOKEN}"
```

с `MODX_MCP_TOKEN="ваш-токен"` в `env` сервера (для сайта на простом HTTP добавьте
`--allow-http`).

### Через Node (мост `modx-mcp`)

Клиенты без HTTP могут запускать мост. Скопировать вариант «Через Node» со страницы «Токены»
в проект (или указать адрес сайта и токен вручную, как ниже), затем переподключить MCP (`/mcp`):

```json
{
  "mcpServers": {
    "modx": {
      "command": "npx",
      "args": ["-y", "github:dampilov94/mcp-component"],
      "env": {
        "MODX_MCP_SITE_URL": "http://САЙТ/assets/components/modxmcp/api.php",
        "MODX_MCP_TOKEN": "ваш-токен"
      }
    }
  }
}
```

## Настройки HTTP-клиента

Дополнительные переменные `env`:

- `MODX_MCP_TIMEOUT_MS` — тайм-аут HTTP-запроса, по умолчанию `60000` мс.
- `MODX_MCP_MAX_REQUEST_BYTES` — лимит тела запроса, по умолчанию `1048576` байт.
- `MODX_MCP_MAX_RESPONSE_BYTES` — лимит ответа, по умолчанию `4194304` байт.

Значения — положительные целые числа. В `MODX_MCP_SITE_URL` указывайте конечный адрес
API: редиректы отключены, токен на другой адрес не пересылается. Для большого ответа
лимит клиента должен соответствовать серверной настройке `modxmcp.max_response_bytes`.

Если запись прервалась по тайм-ауту или отмене, PHP мог уже выполнить действие. В ошибке
будет `request_id`: проверьте его через `modx_request_status`. Для повтора того же
вызова передайте этот ID в `_request_id`, сохранив остальные аргументы. Завершённый
запрос вернёт сохранённый ответ; незавершённый запрос с неизвестным результатом повторно
не выполняется.
